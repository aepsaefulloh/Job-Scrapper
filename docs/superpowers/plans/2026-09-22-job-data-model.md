# Job Data Model Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a private, idempotent job ingestion foundation that stores source payloads, normalized jobs, and deterministic skill hints.

**Architecture:** Source adapters produce a `RawJobInput` contract. `JobIngestionService` validates, canonicalizes, hashes, normalizes, and delegates one atomic persistence operation to a repository. Supabase stores immutable raw observations in `jobs_raw`, the current normalized representation in `jobs`, and child skill hints in `job_skills`, all protected by candidate ownership RLS.

**Tech Stack:** Node.js, TypeScript strict mode, Express conventions, Vitest, Supabase PostgreSQL, Supabase JS, SQL migrations.

**Spec:** `docs/superpowers/specs/2026-09-22-job-data-model-design.md`

## Global Constraints

- Raw source data remains available for audit and reprocessing.
- Normalization, deduplication, and skill extraction are deterministic; no LLM is called during ingestion.
- Scraper adapters must not contain persistence or matching logic.
- No service-role key is used by the API; database access uses the authenticated user's token.
- Every exposed job table has RLS enabled and authenticated-only grants.
- Documentation is written in English; user-facing chat remains Indonesian.

## Review Focus

- URL variants with tracking parameters must converge to one canonical identity; test canonicalization and fallback identity.
- Missing external IDs must deduplicate by `(candidate_id, source, canonical_url)`; test repeated ingestion.
- A changed payload must preserve the previous raw observation while updating the current normalized job; test revision behavior.
- Skill matching must avoid substring false positives such as `go` inside `google`; test token boundaries.
- A candidate must never read another candidate's raw, normalized, or skill rows; pin ownership predicates in migration tests and document the deferred two-user runtime test.
